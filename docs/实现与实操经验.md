# X-AI 的实现与实操经验

## 1.2.7 不能只验证服务启动的瞬间

S06曾有82轮等待，诊断为session不可用，实际4183无监听；S04/S05此前已有成功的媒体请求。恢复服务后，原页面自动完成S06。这说明1.2.6的通道可用，但本机服务生命周期仍不可靠。

检测发现执行环境使用KILL_ON_JOB_CLOSE。DETACHED_PROCESS只隐藏/脱离控制台；普通BREAKAWAY标志仍可能留下外层Job的结束清理约束。实际隔离测试否定了只加标志的方案。最终通过Windows CIM启动固定隐藏后台角色，服务和守护的lifetime均为inJob=false、killOnJobClose=false，并完成“结束启动器进程组、再杀掉测试服务”的恢复验证。

密钥报错来自错误复用ensureIdle，和密钥有效性无关。移除这项限制时必须同时补请求边界校验：等待CD后再次检查密钥，发送检查点前快照，不让停用操作导致空Authorization、未发送却显示unknown或重发已知收费任务。

## 1.2.6 实际Pages来源必须进入验收范围

S04诊断终于确认pageOrigin为https://wangxp7.github.io、localEligible=false、仅direct失败55轮。真实CDN返回200/MP4但没有允许跨域的响应头；在正常Edge中从Pages来源fetch确实失败。此前本机通道下载成功，只证明本机入口可用；手工补项目文件不能证明程序会自动修复后续任务。

这次代码加入显式Pages来源配置、本机媒体会话和自动通道；没有使用公共代理、no-cors不透明响应、关闭web security或重新生成。配置共用、短期凭证绑定Origin、仅固定视频CDN、无API密钥转发。接口早期拒绝时还需有界消耗小请求体，否则Windows关闭含未读POST字节的连接可能让403变为连接重置。

验收必须同时检查：实际origin、模块版本、通道诊断、原video_id、真实视频字节、SHA、完整解码、队列槽位。浏览器本地网络权限要分别验证允许与拒绝，并记录显式授权条件；不能用已授权测试宣称权限可绕过。短暂握手故障使用Runner真实30秒计时恢复，模拟一个失败后仍通过真实服务取片。

维护交接时分清三个状态：代码已修复、发布前环境已验证、公开页面已更新。本轮在线读取仍为1.2.5，不能把隔离页面的1.2.6报告当作公开页面已上线。

## 1.2.5：限流要按操作分开，不把正常排队当成惩罚

用户纠正RPM限制只针对生成提交。旧实现的全局认证锁、state.rate、连接器reserve_slot会让GET和POST互相阻塞；队列pending还触发指数backoff，使正常等待快速扩大为几分钟。本版移除该耦合，POST默认61秒，GET独立10秒，完成即下载。

拆锁时必须同时拆等待截止时间：若循环继续读取共享Transport.nextAt，并行GET可能把POST截止时间覆盖为较早值。现在每次API调用持有局部due；nextAt只用于展示，浏览器并发回归确认等待中的POST不会被GET提前解锁。持久化按平台/操作分别存储，避免两个操作覆盖同一JSON状态。

限流采用加法步长，成功也按步长回落；HTTP Retry-After必须从直连或本机转发获取。正常queued/generating就是成功响应，不应增加惩罚。网络断开不能推断平台限流，未知POST不能因为等待短就重发。完整算法、迁移和边界见设计第39章。

## 1.2.4：先证明失败在哪一段，再恢复原检查点

S03现场记录明确为服务端completed且有原URL；浏览器连续记录direct/fetch_unreadable。同一URL通过真实本机媒体通道和隔离浏览器Transport都成功取回相同SHA，不能再归因为“服务端一直生成中”。旧记录没有页面origin和执行模块版本，不能仅凭fetch异常认定唯一原因是CORS，也不能证明具体哪个缓存条目过期。

本轮补齐全部下载通道诊断、运行版本和模块图版本锁定。仅给app.js加版本参数不能保证其静态依赖刷新；import map覆盖所有src模块，CSP只放行该map的精确哈希。本机JS禁用响应存储；更新需载入新版页面，不尝试在正在发送的收费POST中热替换代码。

原片独立回执解决“字节已写好、project检查点尚未完成”崩溃窗口。先确认任务身份与SHA，再绕过网络退避和离线等待；拒绝同名串任务、篡改和已废弃坏片。测试发现直接返回目录File后回写同一路径会使旧File失效，读取时固化Blob后修复。原片核对可离线，技术检查仍必须实际执行，不能仅改状态为ready。

现场修复先备份，再核对旧记录SHA未被并发改写，最后只合并S03媒体结果。其它镜头、素材、设置、草稿保持；额外保留下载回执，以便旧窗口再次写入旧状态后新版仍可自动找回原片。真实恢复、受控浏览器测试及尚未证明的入口/缓存原因分别记载。

当前总体设计与开发交接请先读 [X-AI详细设计文档](X-AI详细设计文档.md) 或 [HTML阅读版](X-AI详细设计文档.html)。本文件保留实操经验与历史纠错；其中早期界面说明不覆盖用户后来确认的最终设计。

## 为什么按这样的流程组织

源自379镜/40集长期生产流程的关键经验：视频生成是一个可中断、需要保存证据和版本的制作过程，不能把“一次POST成功”当作交付。

1. **先检输入，再发请求。** 时间范围、图片尺寸、声音总长、引用编号、请求体大小均在浏览器检查。剧情拆分和音色身份属于语义问题，不用字符串规则冒充AI判断。
2. **提交前落盘。** 先记录请求摘要、输入哈希、尝试编号，再POST。若返回前页面关闭，下次显示“提交结果待核实”。
3. **video_id独立保存。** 不把task_id或id猜成video_id。查询失败不新建任务；先查询原编号。
4. **所有认证请求共用节流。** 包括GET和连接测试；至少90秒，一个在途任务。只有明确被服务端拒绝创建的限流/队列满才自动重试。
5. **下载和创建分开。** CDN请求不带API密钥。下载出错可以单独重试，手动下载的视频也能导入并校验。
6. **当前版本和历史分别记录。** 重做换版本号、保留原任务；相同任务重新下载而文件内容变化时，另存下载版本，不覆盖旧字节。
7. **实际末帧驱动衔接。** 连续段引用上一镜当前版本的真实末帧，记录来源SHA，不能凭镜号猜旧文件名。
8. **技术、文字、艺术不能混为一谈。** 本平台能检查文件与解码，不能声称已核对角色、台词、动作和音色；用户审核另设状态。
9. **成片再次审计。** 使用实际当前输入清单拼接，对成片重新检查总时长、SHA、完整解码。镜头换版后提示旧成片需要重拼。

## 在实操中见过的问题及平台应对

|实际问题|平台应对|
|---|---|
|本地素材不能当HTTPS URL传入|读真实文件，验证后转Data URI；无需第三方图床|
|横向场景参考偶尔被复制成黑边/模糊填充|默认补充画幅约束，提供抽帧；不认为横图必然失败，也不盲裁人物|
|参考板的文字、白底被画进视频|提示参考用于身份与构图，不复制版式；实际出片人工复核|
|模型把动作说明念成对白|对白单列，禁止念动作/角色名；提供听审与外部AI复核导出|
|ASR输出近音字、幻觉字幕文本|本版不伪造识别结果；需要本地ASR时可外接工具，不把无语音概率当艺术审核|
|分段再次重演前段动作|连续镜加入真实末帧和“继续，不重复”约束；仍需对照实际动作|
|浏览器/网络超时但后台任务可能已建立|冻结未知POST，保存摘要，允许人工绑定video_id或记录未创建的核实依据|
|服务端internal_error/取消|保留错误与原编号，不无限自动创建替代付费任务|
|拼接产生VFR或末尾时长偏差|本地FFmpeg统一24fps/48k，再检查实际成片时长|
|只更新页面，却没更新实际文件|每次执行状态写project.json和MD，文件写入完成后才标已下载|

## 模块

- `src/core.js`：输入验证、导入格式、状态常量、密钥AES-GCM保险箱、摘要与敏感信息清理。
- `src/storage.js`：IndexedDB工作副本、目录授权、原子文件写入、MD导出。
- `src/media.js`：图片与声音解码/派生、MP4检查、抽帧、单线程FFmpeg WASM完整解码和拼接。
- `src/engine.js`：HTTP节流、唯一生成队列、恢复策略、当前与历史尝试、按集组装。
- `src/app.js`：界面与人工操作、导入导出、审核、版本选择。
- `src/credentials.js`：默认密钥、普通换 KEY 与高级保险箱操作。
- `src/local-default.js`：仅供本机私有配置的免口令密文封装，不将这种模式描述为可公开保密。
- `tools/serve.py`：本地静态服务器；生产站点不需要它。
- `tools/connector.py`：可选本机跨域连接器，不持久保存KEY。

## 一致性和锁的范围

Web Locks在同一浏览器/同一源内禁止第二个可写工作台，HTTP请求另有锁和持久时间戳。连接器也对相同KEY的指纹记录最近认证请求时间。它们无法控制另一个设备、另一个浏览器或旧版Python生产程序，所以必须由账户使用者避免多处同时运行。

项目JSON不包含文件内容或明文KEY；文件字节在本地目录和浏览器工作副本内。绑定原ID、确认未创建、切换当前版本、重新生成均是独立操作，避免一个“重试”按钮误触发所有阶段。

## 目前没有自动完成的事

没有自动语音克隆、Whisper转写、AI视觉审片、人物重绘、智能切分剧本、自动无限重做或网站后台调度。界面明确提示这些需要人工或外部工具。程序不会把“已检测”冒充“内容已合格”。

关闭标签页后没有Service Worker继续执行付费任务；需要持续运行就保持电脑和页面唤醒。网络恢复后继续查询原任务。

## 2026-09-30恢复与部署收尾

- **目录覆盖风险**：选择目录时先读取 `project.json`。已存在的项目必须恢复后再写，取消不改动文件；不把空工作副本盖到旧项目上。
- **历史记录一起恢复**：原始下载、当前版本、旧下载版本、末帧、五点抽帧及分集成片一并检查。哈希不符时停止切换。
- **磁盘File不是永久快照**：文件在外部改动后，旧File句柄可能抛出NotReadableError。导入缓存前复制真实字节，避免把磁盘引用误认为独立备份。
- **重复标签页不能先写后锁**：先取得工作台锁，再载入并更新状态。第二页只显示重新连接提示。
- **身份验证失败要止损**：401/403暂停新提交，保留其余待提交项；不会将整批分镜逐个标为失败。
- **待核实提交和历史下载分开**：POST无video_id须核实；同一任务重新下载不同字节使用独立下载序号，保留此前检查材料。
- **同名参考文件不能猜**：清单中文件名对应多个资产时，要求使用明确ID；不自动引用第一张。
- **时间容差的含义**：请求仍只允许4–12秒整数。MP4容器允许最多0.05秒音频封装尾差，超过12.05秒或偏离计划0.25秒会判为时长问题；不擅自切掉镜头内容。整集允许0.5秒封装/编码偏差。
- **检查许可证版本映射**：ffmpeg.wasm仓库标签v12.15对应core包0.12.10，不能把相近标签名当成同一版本。可用源码、构建说明和哈希随仓库提供。

以上问题的修正经过规则测试、浏览器恢复测试和本地媒体处理测试，详见《验证记录》。真实视频艺术质量仍需要人工观看、听审。

## 2026-10-01 再调整：紧凑工作台与普通密钥模式

用户反馈大型宣传页头、分散的目录按钮占用了有效面积，密钥入口步骤过多。本次去掉装饰 Hero、解除 1530px 内容宽度上限，压缩顶栏/表单间距。文件夹文字和选择按钮放在一起，右侧使用实际项目数据展示待处理、已生成、素材数量；保留正文 15px、说明至少 14px，不用缩放页面来挤空间。

免口令使用和口令保护有不同的边界：默认配置中 KEY 虽非明文，但开启材料也在该本机文件中，完整文件的持有者可以恢复 KEY。整个 private 目录必须排除 Git 和公共站点；不能用“加密”一词声称纯前端共享密钥无法被提取。该改动不需要静态服务器增加解密接口。

提示层级以原生 dialog 为准：设置错误进入弹窗底部的固定反馈区，其他弹窗进入自身的消息区；不依赖提高背景 toast 的 z-index。打开设置时移除旧背景提示，任意 modal 打开期间隐藏背景提示容器。错误字段自动聚焦，但反馈区保持在可见视口内。

## CSV、目录授权与原路径引用（2026-10-01）

解析器独立为 batch.js，core 保留兼容导出。表头识别分隔符、字段优先级明确，CSV 引号状态内的换行与分段符不拆行；列数不符必须报错，不截掉多余字段。中文集名映射只在本批有效，跨批应明确指定 episode。

浏览器选单个 CSV 不会授予读取父目录的能力。BatchPanel 单独请求只读根目录，再记录清单相对位置，逐段归一化 ../，越界报错。索引不读媒体字节，明确引用全部定位成功后进入已有素材校验进度。File System Access 不可用时用 webkitdirectory，只有用户选中文件的工作缓存；目录句柄可用时提交前重新读源文件并验证哈希。

原路径素材标记 storage=source；保存项目和迁移输出目录时跳过原文件复制。sources/aliases 追踪路径与编号，effectiveAssetId/derivedFrom 追踪优化关系。请求编码、待提交分镜和 reference-mapping.json 同步使用有效素材。新建 source 素材时完整保留文件名，不用带哈希的新名字代替原路径。PNG/WebP 同名优化必须真正输出 PNG/WebP，声音同名裁切也要实际保留容器和编码，不能只改后缀。

选目录先备份已有 references，逐文件 SHA-256 回读验证，并生成备份清单。写覆盖文件前再次备份，旧版本记录指向备份。两个不同原路径恰好同名时用 references/素材ID/原文件名；源文件本就在 references 的目标位置时也另用子目录，防止修改原件。

浏览器测试比较请求中的 Base64 解码字节与优化结果哈希。测试代码不能 fetch(data:...)，页面 CSP 不允许这种连接；直接解码 Base64 能完成同样核验且不扩大网页权限。


## 递归引用解析（2026-10-01）

`src/references.js` 按内容类型递归处理 TXT、Markdown、JSON、CSV / TSV 和媒体目录。解析器只接受明确的文件语法：文件列、直接路径、Markdown 链接、`{{file:...}}`、`@file(...)`、JSON `$ref`。多镜文件按镜号 / 标题 / JSON Pointer 取片段，不把其他镜头整份灌进提示词，不把文件内 API 设置混入任务。

每层解析携带该文件路径和调用链；素材解析成根目录下的规范路径，再换算成相对最初 CSV 的引用。图片 / 声音按规范路径去重，最后按实际图像、音频序号生成占位符。媒体清单按“素材”上下文处理，不能直接把清单原文当画面描述。

循环检查使用路径加片段定位，另有深度、文件数、字节数、展开字符和操作次数上限；文件读取缓存与递归调用栈分开，避免把正常复用误判循环。入队前回读文本哈希；成功后保留文本快照，生成过程不再悄悄替换文案。原 CSV 和原素材不改写。来源链 / 哈希写进任务、提交尝试快照和制作 MD，方便复查。

回归中发现：识别正文 `../文件` 的规则如果直接用于所有素材列，会让普通图片路径也被误认为嵌套文本，破坏原来的预览流程。现已区分“直接媒体路径”和“需要展开的链接 / 清单”，加了专门回归。素材 CSV 的 `编号,路径` 表头也不能依赖只识别镜头表头的分隔符检测，需按素材字段检测。

浏览器检查用临时 OPFS 目录、合成媒体和隔离配置，不读取用户生产素材、不发计费请求；比较实际构造的请求内容、导出的来源记录与原图哈希。HTML 示例只经转义展示，不能成为 DOM。

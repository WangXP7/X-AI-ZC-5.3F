# 批量清单与原路径素材

## 推荐操作顺序

1. 切换“多段一次生成”。进入独立的紫色批量操作区，单段提示词、上传框及参数会隐藏；直接操作下方分镜清单。
2. 点击“选择清单与素材目录”，选包含清单及其所有参考素材的共同上级目录；再从下拉框选清单的位置。此权限只用于读取素材，与顶部的输出目录不同。
3. 点击“读取引用并展开”。先递归展开文本并显示替换前后；路径全部定位成功后，先展示校验清单，再逐项导入索引。原文件不复制到 references。
4. 点击“预览字段与匹配”，核对镜号、秒数、分组、提示词和素材。原表的历史版本、审核说明、试音列不会盲目混入当前参考。
5. 在素材库处理标记不合格的图片或声音。合格优化版保存到输出目录 references，原路径自动映射到当前优化版。
6. 回工作台再次预览，检查整批入队。实际付费生成仍需到任务页点击“开始 / 继续队列”。

只用“导入清单文件”读取 CSV 时，浏览器不会透露其父目录，不能凭这个文件访问旁边素材。需选择一次共同上级目录、在目录列表中选清单，才能定位 `../`。已有素材的文件名、编号、ID 可直接匹配，无需重复添加。

## 批量默认设置

清单下方的“批量默认设置”默认收起，摘要显示当前时长、画幅、分组和共用素材数量。展开后可调整缺省参数，并选择共用参考；它们只补齐清单没有填写的字段。镜号没有填写时按本模式的自动镜号前缀编号。单段的镜号、提示词、对白、随机种子、首尾帧和参考列表独立保留。

从批量模式打开素材库后，选择按钮会写“用于批量共用素材”。明确写了 `files` / 参考图 / 参考声音的分镜依然使用自身引用；空列 / 空数组表示无参考。

## 格式与限制

- CSV 一行代表一个分镜，不需要 `---`；带引号的单元格内可以换行、写分隔符或 `---`，不会被拆镜。
- 自动识别英文 / 中文逗号、制表符、英文 / 中文分号、竖线。表头至少包含两个已支持字段才按表格解析。未知格式不会自动推断剧情。
- 纯文本按独立一行的 `--`、`---`、`===`、`***`、`___` 分段；段内标点不拆分。
- 每批 1–1000 镜、10MB 以内。目录索引最多 20000 个文件、64 层；`.git` 目录不索引。
- 表头重复、空列、行列数不一致、引号未闭合会指出行号，不静默丢弃字段。用电子表格“另存为 CSV UTF-8”能正确处理字段引号。

## 主要字段

|用途|支持字段（按优先顺序选取非空值）|
|---|---|
|镜号|id、镜号、镜头编号|
|分组|episode、分集、分组、集名|
|提示词|AgnesAI实际提示词、prompt、提示词、画面动作、画面与动作、画面描述|
|时长|seconds、秒数、时长秒、时长；整数 4–12|
|比例|aspect_ratio、aspect、画面比例、比例|
|生成方式|mode、生成模式、生成方式；text / reference / keyframe 或文字生成 / 参考生成 / 首尾帧|
|对白|dialogue、对白、指定对白、台词；“对白功能”是说明列，不当作真实台词|
|全部参考|assetIds、files、素材、参考素材、参考文件、素材编号、素材路径|
|仅图像|images、image_paths、参考图、图片路径、图像路径、当前图像引用、当前图像候选引用|
|仅声音|audio、audio_paths、参考声音、声音路径、音频路径、声音参考|
|首尾帧|first_frame / 首帧、last_frame / 尾帧|
|衔接|continuity_from、衔接镜号|

存在“全部参考”列时以该列为准，否则组合图像和声音列。明确空列或空数组表示无参考；未提供引用列时使用“批量默认设置”里的共用参考素材；不继承单段模式的选择。引用非空且未写 mode 时自动采用参考模式，写首尾帧时采用首尾帧模式。中文集名按本批出现顺序映射 EP01、EP02…，原集名保留在记录中，预览可检查；跨批次建议明确使用固定 episode 编号。

未识别列会在预览中列出。历史五视图、5 秒 / 12 秒试音、审核状态、待办建议等只作说明。平台不会从长说明里猜哪个版本通过了艺术审核；请将当前确定的文件填入引用列。

## 递归文本与素材清单引用

选择共同上级目录后，点击 **读取引用并展开**。平台在本地按明确的格式和定位规则解析，支持“CSV → JSON → Markdown → TXT”多层引用；不会执行文件里的指令、脚本或程序，也不会调用另一个 AI 去猜剧情。

|文件 / 内容类型|处理方式|
|---|---|
|TXT|读取全文；内容中的引用继续展开|
|Markdown|使用 `#标题` 选择片段；没有指定标题时，优先匹配当前镜号标题|
|JSON|使用 `#/字段/子字段` 定位；也支持按镜号匹配 `shots` 数组或镜号键|
|CSV / TSV|按当前镜号或 `#镜号` 选择记录，再展开其中提示词、对白和素材|
|素材清单|引用列中的 JSON / TXT / Markdown / CSV 按素材目录处理，继续读取里面的图片、声音路径或下级清单|
|图片 / 声音|按引用文件所在目录定位；正文链接转换为 `<Picture n>` / `<Audio n>` 并加入该镜参考，重复素材合并|
|PDF / Word / Excel 等|提示转换为 TXT / Markdown / JSON / CSV；不会把二进制内容当提示词|

文本引用写法：

```csv
镜号,时长秒,提示词文件,对白文件
A01-01,8,../提示词/镜头.json,../声音/台词.json#/开场
```

`镜头.json` 可写：

```json
{
  "shots": [{
    "id": "A01-01",
    "prompt": "[动作](动作.md#开场)",
    "files": ["C01=../图片/小熊.png"]
  }]
}
```

同目录的 `动作.md`：

```markdown
# 开场
{{file:公共风格.txt}}
小熊抬头看向远处的灯火。
![角色](../图片/小熊.png)
[参考声音](../声音/环境.wav)

# 下一镜
这里不进入开场提示词。
```

其中 `公共风格.txt` 还能继续引用其他文件。每一层的相对路径都以 **这一层文件所在目录** 为基准；最终素材路径重新表示为相对原 CSV 的路径，原文件不移动、不改写。带空格的 Markdown 链接使用 `[风格](<../公共 风格.txt>)`。

还支持提示词单元格直接写 `../提示词/动作.md#开场`、正文内 `@file(../公共风格.txt)`、`{{引用:../公共风格.txt}}`、明确的 `./` 或 `../` 文件路径，以及 JSON 的 `{"$ref":"其他文件.txt"}`。推荐正文使用 Markdown 链接或 `{{file:...}}`，避免与普通句子混淆。

新增列：`prompt_file / prompt_path / prompt_ref / 提示词文件 / 提示词路径 / 提示词引用`、`dialogue_file / dialogue_ref / 对白文件 / 台词文件 / 对白引用`。非空文件列优先替换整个对应字段；要拼接现有文字，请在提示词正文内插入引用。多个文件可用 `|`、分号或字符串数组，按顺序以空行连接。不会从引用文件覆盖时长、密钥或 API 设置。

素材目录 JSON 可使用 `{"files":["子清单.md"]}`、`{"C01":"图片/小熊.png"}`，或 `[{"id":"C01","path":"图片/小熊.png"}]`。素材 CSV 使用 `编号,路径`（也支持其他已识别分隔符），可用 `目录.csv#C01` 只取该编号。首尾帧引用的清单必须最终只对应一张图片。

### 预览、错误与来源记录

- 页面显示读取文件数、文本替换数、每处替换前后、来源文件与 SHA-256；下载展开后的清单可查看完整引用链。原 CSV 保持原样。下载文件的素材路径仍相对原 CSV 所在目录；重新导入时放在同一位置或调整路径。
- 一份文件含多个镜头时必须匹配到当前镜号，或使用唯一标题 / JSON 定位。标题重复、镜号缺失、同名歧义、循环引用、路径越界、文件缺失会阻止整批入队，不猜测其他片段。
- 引用失败会列出镜号、文件或引用链。修正源文件后再次点“读取引用并展开”，无需重复逐个上传媒体。
- 文本只在本次展开时缓存；入队会重新读取并比对哈希。预览后源文件变化则要求重新展开，不能拿旧预览入队。
- **入队后使用已确认的文本快照**，不随磁盘变化自动重写任务。需要新文本时重新展开并建立 / 修订分镜；已有远端任务继续原 video_id。图片、声音在实际提交时仍会回读原文件并核对哈希。
- `project.json`、提交尝试快照和制作 MD 保留各镜文本来源、选择位置、引用链和哈希。文档中的说明或脚本只作为数据，不成为平台指令。
- 每次最多 12 层、500 个不同文本文件；单文件 2MB，合计 10MB；单字段展开后最多 12000 字，展开结果总计最多 10MB。超限提示拆批或缩小引用片段。重复文件只读取一次，但显式重复插入的文字按编排保留。
- 文本支持 UTF-8、带 BOM 的 UTF-16；旧中文文件尝试 GB18030 并提示核对。建议统一 UTF-8。外部网页不抓取；需要外部内容时保存为本地文本后明确引用。

## 路径例子

```text
项目根目录/
  分镜/第一集.csv
  图片/C01_小熊.png
  声音/R01_对白.wav
```

选择“项目根目录”后，第一集.csv 可写：

```csv
镜号,时长秒,提示词,参考图,参考声音
A01-01,8,小熊走进森林,C01=../图片/C01_小熊.png,R01=../声音/R01_对白.wav
A01-02,6,小熊回头,C01,R01
```

多个引用在同一单元格用 `|` 或分号隔开，也可使用 JSON 字符串数组。CSV 单元格本身含所用分隔符或换行时必须加双引号，内部双引号写两次。

支持 `/` 和 Windows 的反斜线。`../` 只能在已授权根目录内向上一级。绝对路径、网址、越出授权目录、文件缺失、同一编号多个版本都会报出具体引用；不会自动访问外部网址、猜一个同名文件或丢掉某个参考继续提交。比如 C01 有正视图和历史五视图两份时，必须写准确路径。

## 素材库与优化关系

素材库中的 UUID 是精确标识，卡片“原路径引用”详情可展开查看路径、编号和 ID。编号 C01 也可匹配唯一的 C01_ 文件名；多个候选时报错。清单 `C01=路径` 会登记该编号。重复文件按 SHA-256 复用，并保留本次路径与编号信息。

原路径不变，优化版路径会写入 `project.json` 和 `reference-mapping.json`，处理和提交时自动使用有效版本。读取目录不改变原剧本 / CSV 的任何字节。技术校验通过不代表人物、对白或剧情已审核。
